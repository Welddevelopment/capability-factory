# Shared capability-mode package hardening checkpoint — 2026-07-31

## Result

The additive customer-local capability-mode package now has reusable operational controls
across browser, file/EDI, inbox and document drivers without changing the constrained-HTTP
pilot installer or merging mode evidence.

## Lifecycle and recovery

The package now supports:

- explicit deactivation with a bounded redacted reason;
- startup refusal while deactivated;
- stopped-sidecar backup only;
- exact recursive backup of config, pinned contracts, private credentials, durable mode jobs
  and separate mode registry/state;
- a manifest containing every relative path, byte count and SHA-256 digest;
- refusal of symbolic links, unexpected files, missing files and changed payload bytes;
- exact restore while preserving the separate backup archive; and
- restored readiness and customer-local credentials after returning to an earlier active
  checkpoint.

SQLite write-ahead-log or shared-memory files cause backup to stop and instruct the operator
to close the sidecar first. The implementation does not claim a hot live-database snapshot.

## Evidence and support exports

The package can now emit immutable local exports:

- a sanitized evidence export containing installation/mode metadata, pinned contract hashes,
  readiness, a supplied report hash and a recursively redacted copy of the report; and
- a support bundle containing readiness plus storage presence/privacy posture.

Neither export copies secret values. The support bundle does not copy customer payloads or
database content. Credential-like keys and bearer values in supplied reports are redacted.
Existing output paths are never overwritten.

## Operator command surface

`pnpm mode-package` exposes:

- `doctor`;
- `backup`;
- `verify-backup`;
- `restore`;
- `deactivate`;
- `evidence`; and
- `support`.

Customer-specific runtime startup remains generated by the adapter/package integration because
the package must not guess a driver, target or verifier.

## Package/tool and database mode no-go

The census-based reassessment did not justify implementing package/tool installation or direct
database actions in this pass. Their raw ledger counts are small and the clean incremental
buyer unlock becomes roughly one package case and two database cases after removing
competitors and implementation firms. Their supply-chain and credential/blast-radius surfaces
are materially wider than the existing bounded modes. Reopening conditions are recorded in
`docs/MODE_EXPANSION_GO_NO_GO_2026-07-31.md`.

## Evidence boundary and remaining blockers

This is local fictional product hardening. It does not establish production operations,
customer backup/restore compatibility, disaster-recovery objectives, external security
approval, encrypted off-host backups, key management, multi-host failover, a hosted control
plane or a formal final green verdict.

Product work cannot remove blockers that require:

- a real customer's workflow, system and credentials;
- founder conversations and last-ten-deployments evidence;
- willingness to pay, buyer authority or procurement;
- regulated-data approval and legal authority;
- representative MFA/SSO/network/security constraints;
- an external held-out customer system;
- production monitoring and incident response under real use; or
- repeatable customer onboarding evidence.
